# 개발 상태 — 2026-09-30

브랜치: `codex/combat-prototype`

## 범위 결정

사용자가 제공한 개발지침 0.2를 개발 기준으로 채택했다. 외부 문서에 있는 추가 작업을 무조건 실행한 것이 아니라, 사용자의 “지침대로 개발 분기를 작성하면서 진행” 요청에 맞춰 구현 순서를 적용했다.

이번 체크포인트는 **5개 발판의 플레이 가능한 전투 실험실**이다. 지침 6.4절은 “공격 유도→회피→반격 사례와 공격자의 반대 방향 견제 사례를 영상으로 확보하기 전에는 전체 맵을 확장하지 않는다”고 정한다. 자동 스크립트는 이 사람 대상 검증을 대신하지 않으므로 전체 맵으로 확장하지 않았다.

## 구현 계약

- Python 3.12.10, pygame-ce 2.5.7 (SDL 2.32.10), PyInstaller 6.16.0. 실제 설치 해석 결과는 `requirements-lock.txt`에 고정했다.
- pygame은 창·그리기·입력·소리 담당. 물리는 자체 모터이며 시뮬레이션에서 pygame을 import하지 않는다.
- 자유 낙하는 고정 1/60초의 반암시적 오일러 적분으로 목표 속도를 계산하고, 직선 스윕으로 교차 시점을 찾는다. 착지 후 남은 수평 이동·발판 이탈·벽 충돌을 분할 처리한다.
- 수평 넉백은 단일 velocity 계약. 피격 다음 틱부터 14회 이동에 마찰·입력 없음. 추가 적중과 벽 충돌만 속도를 바꾼다.
- 상태를 수정하는 쪽은 시뮬레이션과 명시적 디버그 도구뿐이다. 렌더러는 읽기 전용이다.
- 장시간 프레임 지연에서도 누산 시간을 버리지 않는다. 한 표시 프레임에 240틱까지 처리하고 남은 적체를 다음 프레임으로 넘긴다. 디버그 HUD에 적체를 표시한다.
- 표준 SDL 컨트롤러 ID로 슬롯 유지; 해제 시 일시정지, 눌림 상태 제거. 지원하지 않는 비표준 장치는 키보드 보조 입력을 사용한다.
- 기록은 설정/맵/빌드, 시작 상태, 매 틱 입력·해시, 60스텝마다 스냅샷, 적중·종료 이벤트를 포함한다. 재생 차이는 최초 불일치 스텝/틱으로 보고한다.

## 다음 개발 작업

1. 두 사람이 F3/F4로 시작 조건을 바꾸고 조작자를 교대해 압박 실험을 수행한다. 표본과 영상에서 이동만으로 탈출하는 비율·회피 후 반격·반대 방향 견제를 확인한다.
2. 80% 탐지 기준을 넘는 상황이 실제 대전에서도 반복되면 공격 범위 또는 준비 시간 하나만 변경한 비교 실험을 한다. 몸체 충돌 B는 별도 접촉 규칙을 정한 후 검토한다.
3. C 조건 통과 후 105초부터 시작하는 마지막 15초 장면을 UI에 연결하고, 네 가지 체력 조합과 자유 대응을 비교한다.
4. 이후 전체 대칭 맵, 이동 경로 검사, 공동/분할 카메라를 추가한다.
