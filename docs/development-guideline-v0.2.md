# 부서진 마천루 — 상세 개발 지침

버전: 0.2 / 작성일: 2026-09-30 / 기준 자료: 첨부된 「초안.md」

이 문서는 초안의 게임을 실제 시제품으로 구현하기 위한 설계 제안이다. 초안에서 확정하지 않은 플랫폼·좌표·수치·예외 처리는 아래의 초기 구현안으로 정의한다. 수치는 플레이 테스트 전의 가설이며, 검증된 밸런스나 실제 개발 완료 상태를 뜻하지 않는다. 특정 엔진의 API에 의존하지 않도록 작성했다.

이번 개정은 설계 검토의 다섯 항목을 반영한다. 넉백·동시 입력·점프 버퍼·착지 교차 시점은 구현 계약으로 명확히 하고, 몸체 통과와 종료 직전 점프는 아직 검증되지 않은 전투 가설로 남긴다. 아래 테스트는 수행 지침이며 실행 결과가 아니다.

## 1. 목표와 개발 범위

### 1.1 반드시 지킬 게임의 중심

두 플레이어는 건물 상층에서 시작한다. 밀치기로 상대의 위치를 무너뜨리고, 아래로 내려오는 하얀 막을 피해 함께 하강한다. 최하단 추락 또는 체력 소진은 탈락이며, 제한 시간에는 높은 플레이어가 이긴다.

개발 중 기능을 추가할 때는 다음 질문에 답해야 한다.

1. 이 기능이 가장자리에서 공격·회피·반격의 선택을 만드는가?
2. 높이를 지키는 이점과 내려가야 하는 압박을 강화하는가?
3. 추락 후 착지와 재교전의 가능성을 유지하는가?
4. 공격에 맞거나 패배한 이유를 플레이어가 이해할 수 있는가?

이 질문에 기여하지 않는 기능은 첫 시제품에서 미룬다.

### 1.2 작업 기준

| 항목 | 초기 구현안 |
|---|---|
| 화면과 이동 | 2D 측면 시점, 수직으로 긴 고정 맵 |
| 플랫폼 | PC 실행형 시제품 |
| 기본 대전 | 한 기기에서 2인 로컬 대전 |
| 입력 장치 | 게임패드 2개 우선, 키보드 분할 입력 보조 |
| 콘텐츠 | 동일 성능 캐릭터 1종, 고정 맵 1개 |
| 경기 | 단판 120초, 3초 시작 카운트다운 별도 |
| 시뮬레이션 | 고정 60틱/초, 표시 프레임과 분리 |
| 아트 | 단색 도형으로 시작하고 판정 확정 후 교체 |
| 후속 범위 | 무너지는 발판, 온라인 방 대전, 외형 꾸미기 |

첫 시제품에는 계정, 매칭, 랭킹, 상점, 여러 캐릭터, AI 상대, 절차적 맵 생성, 파괴 가능한 건물 전체를 포함하지 않는다. 단, 혼자 검증할 수 있는 입력 재생 봇과 정지 표적은 개발 도구로 제공한다.

## 2. 경기 규칙을 코드로 고정하기

### 2.1 좌표와 판정 기준

- 월드의 위쪽이 +Y이며 모든 물리 수치는 월드 단위를 사용한다.
- 플레이어 위치는 발밑 중앙 좌표로 저장한다. 높이 승부와 막 노출은 이 좌표를 사용한다.
- 캐릭터의 초기 충돌 크기는 너비 0.8, 높이 1.6이다. 스킨·이펙트 크기는 판정을 바꾸지 않는다.
- 화면 밖으로 나가는 것은 탈락 조건이 아니다. 카메라와 승패 판정을 분리한다.
- 낙하 피해는 없다. 체력은 하얀 막 노출로만 감소한다.
- 최하단 경계는 Y=-2.0이며, 발밑 Y가 이 값 이하이면 탈락한다.

### 2.2 상태와 시간

경기 상태는 `Loading → Countdown → Playing → Result`로 진행한다. 로컬 일시정지는 별도 상태로 두어 게임 틱, 막, 체력, 쿨다운, 경기 시간을 함께 멈춘다. 결과 화면에서는 재경기 또는 나가기를 선택한다.

카운트다운에는 이동·공격을 허용하지 않는다. 카운트다운 중 눌렀던 점프·공격·회피는 시작 순간 자동 실행하지 않으며, 새로 누른 입력부터 인정한다. 방향 입력은 경기 시작 시 현재 입력을 읽는다.

60틱 기준으로 경기 시간은 정확히 7,200틱이다. 남은 시간은 틱으로 계산하고 UI에 초 단위로 표시한다. 실시간 시계나 애니메이션 재생 길이를 승패 계산에 쓰지 않는다.

### 2.3 승패 우선순위

한 틱에서 두 플레이어의 이동·피격·환경 피해를 모두 처리한 뒤 한 번만 결과를 평가한다.

| 우선순위 | 조건 | 결과 |
|---|---|---|
| 1 | 같은 틱에 두 명 모두 탈락 | 무승부 |
| 2 | 한 명만 탈락 | 생존자 승리 |
| 3 | 탈락 없이 제한 시간 종료, 높이 차이 > 0.1 | 높은 플레이어 승리 |
| 4 | 시간 종료, 높이 차이 ≤ 0.1, 체력이 다름 | 체력이 많은 플레이어 승리 |
| 5 | 높이 동률 범위이며 체력도 같음 | 무승부 |

같은 틱의 체력 0과 바닥 추락은 모두 탈락으로 처리한다. 시간 종료 틱에 탈락이 발생하면 탈락 판정이 높이 판정보다 먼저다. 결과 확정 후에는 추가 충돌이나 피해로 결과를 바꾸지 않는다.

시간 종료 높이는 공중 상태도 포함한 최종 발밑 높이다. 따라서 마지막 점프가 승부에 영향을 줄 수 있다. 이것은 초기 규칙이며, 플레이 테스트에서 불쾌한 막판 점프 경쟁이 지배적이면 착지 기준 등 다른 규칙을 별도 실험한다. 문서와 코드의 규칙을 동시에 변경한다.

## 3. 조작과 이동

### 3.1 입력 행동

| 행동 | 기능 | 초기 제약 |
|---|---|---|
| 좌우 이동 | 지상·공중에서 수평 방향 조절 | 대각선 입력은 수평값만 사용 |
| 점프 | 지상에서 위로 도약 | 공중 추가 점프 없음 |
| 아래+점프 | 현재 발판을 통과해 하강 | 착지 중인 단방향 발판에서만 가능 |
| 밀치기 | 바라보는 방향의 근접 공격 | 지상·공중 모두 허용 |
| 회피 | 현재 위치에서 짧게 공격 무적 | 지상·공중 허용, 이동과 중력 유지 |
| 일시정지 | 로컬 경기 중 메뉴 표시 | 온라인 확장에서는 경기 정지 금지 |

내려가기 입력은 초안에 명시되지 않은 보완안이다. 발판 가장자리까지 매번 이동하지 않아도 하강 시점을 선택하게 한다. 아래+점프를 감지한 틱에는 일반 점프를 실행하지 않는다.

키는 입력 행동에 바인딩한다. 소스 코드에서 특정 키를 직접 검사하지 않는다. 같은 키보드의 동시 입력 제한은 장치마다 다르므로, 키 재지정과 게임패드 지원으로 대응하고 실제 장치로 확인한다.

### 3.2 이동 초기값

| 설정 키 | 초기값 | 의미 |
|---|---:|---|
| runSpeed | 6.0 단위/초 | 지상·공중의 목표 수평 속도 상한 |
| groundAcceleration | 60 단위/초² | 지상 가속 |
| groundDeceleration | 75 단위/초² | 지상 무입력 감속 |
| airAcceleration | 24 단위/초² | 공중 가속·제동 |
| gravity | 30 단위/초² | 중력 크기 |
| jumpVelocity | 11 단위/초 | 점프 시작 수직 속도 |
| terminalFallSpeed | 18 단위/초 | 최대 낙하 속도 |
| coyoteTicks | 6틱 | 발판을 벗어난 직후 점프 허용 |
| jumpBufferTicks | 6틱 | 착지 직전 점프 입력 보관 |

이 초기값의 이론상 점프 최고 높이는 약 2.02단위다. 같은 높이로 돌아오는 시간은 약 0.73초이며, 수평 속도 6을 유지하면 약 4.4단위 이동한다. 이는 충돌·가속을 제외한 참고값이므로 맵의 이동 가능 여부는 실제 모터로 검증한다.

이동 처리는 목표 속도를 향해 가속하는 방식으로 작성한다. 입력이 바뀌었다고 즉시 최대 속도로 덮어쓰지 않는다. 실제 운동 속도는 `velocity` 하나만 사용하고, 피격 상태로 제어 허용 여부를 구분한다. 별도의 넉백 속도를 중복 합산하지 않는다. 피격 중 속도 계약은 4.3절을 따른다.

코요테 점프는 발판을 걸어서 벗어난 경우에만 허용한다. 피격으로 밀려났거나 아래+점프로 내려간 직후에는 허용하지 않는다. 점프를 한 번 소비하면 코요테 시간과 입력 버퍼를 모두 지운다.

### 3.3 충돌 정책

- 발판은 위에서 내려올 때만 착지하는 단방향 지형이다. 아래에서 점프하면 통과한다.
- 착지는 하강 중 발밑이 발판 상단을 통과하는 **교차 시점의 수평 구간**으로 판정한다. 상세 계산은 3.4절을 따른다.
- 빠른 낙하에서도 발판을 통과하지 않도록 이전 위치부터 목표 위치까지의 이동 구간으로 충돌을 검사한다.
- 여러 발판을 한 틱에 통과하면 이동 경로상 처음 만난 유효 발판에 착지한다.
- 아래+점프는 현재 지지 발판 ID만 무시한다. 모든 발판 충돌을 끄지 않는다.
- 무시 상태는 캐릭터 몸 전체가 해당 발판 아래로 내려가면 해제한다. 하강 시작 시 작은 하향 속도를 주고, 중력이 진행되게 한다.
- 기준 실험안 A에서는 두 캐릭터가 서로 통과하고 공격 판정만 상호 작용한다. 이는 최종 확정 규칙이 아니다. 6.4절의 가장자리 압박 실험이 끝나기 전에는 통과 여부와 공격 범위를 확정하지 않는다. 상대 머리 위에 서는 동작은 지원하지 않는다.
- 좌우 맵 경계는 벽으로 막는다. 벽에 닿아도 탈락하지 않으며, 벽에서 발판으로 돌아갈 가능성은 유지한다.
- 같은 위치에 겹친 캐릭터는 외곽선과 P1/P2 표시로 구분한다.

### 3.4 대각선 착지와 교차 시점

한 틱의 물리 적분으로 얻은 발밑 시작점 `p0=(x0,y0)`, 목표점 `p1=(x1,y1)`을 직선 이동 구간으로 취급한다. 엔진이 여러 하위 이동 구간으로 나누면 각 구간에 같은 검사를 적용한다. 발판 상단은 H, 좌우 끝은 L/R, 캐릭터 반폭은 r=0.4다.

하강 `y1<y0`이며 `y0≥H≥y1`인 후보에 대해 다음을 계산한다.

```text
alpha = (y0-H)/(y0-y1)
xCross = x0 + alpha*(x1-x0)
overlap = min(xCross+r, R) - max(xCross-r, L)
validLanding = overlap > collisionEpsilon
collisionEpsilon = 0.00001 월드 단위
```

양의 면적 겹침이 있어야 착지한다. 모서리끼리 정확히 닿는 것은 지지로 인정하지 않는다. 무시 중인 발판과 붕괴한 발판은 후보에서 제외한다. 유효 후보 중 alpha가 가장 작은 충돌을 먼저 해결하며 동시 후보는 발판 ID 순으로 결정한다. `collisionEpsilon`은 높이 승부의 0.1과 별도 설정이다.

교차 지점으로 이동한 뒤 하향 속도를 0으로 하고, 남은 틱 시간의 수평 이동을 계속 처리한다. 그 이동으로 발판을 벗어나면 남은 구간에 중력과 충돌을 다시 적용한다. 한 번 착지했다는 이유로 틱 종료까지 발판에 붙이지 않는다. 벽 충돌이 먼저 발생하면 그 지점에서 이동 구간을 나누고 벽 바깥쪽 속도를 제거한 뒤 다시 검사한다.

이미 지지 중인 상태는 별도 지지 검사로 유지한다. 상승 속도가 생기거나 수평 겹침이 사라지면 지지를 해제한다. 하강 교차식의 분모가 0인 수평 이동에 착지식을 적용하지 않는다.

## 4. 밀치기와 회피

### 4.1 행동 상태

행동 상태는 `Neutral`, `AttackStartup`, `AttackActive`, `AttackRecovery`, `Dodge`, `Hitstun`, `Eliminated`로 구분한다. 지상/공중은 별도 이동 상태다. 애니메이션은 상태를 보여 주며 게임 판정을 직접 결정하지 않는다.

| 행동 | 진입 조건 | 종료 조건 | 취소 규칙 |
|---|---|---|---|
| 공격 | Neutral에서 공격 입력 | 준비·유효·후딜 종료 | 피격으로만 취소 |
| 회피 | Neutral이고 쿨다운 0 | 15틱 경과 | 무적 밖에서 피격하면 취소 |
| 피격 경직 | 유효 공격 적중 | 14틱 경과 | 점프·공격·회피로 취소 불가 |
| 탈락 | 체력 0 또는 바닥 경계 통과 | 경기 종료 | 다른 상태로 복귀 불가 |

입력은 틱 시작 상태를 기준으로 아래 표와 순서에 따라 처리한다. `실행`은 조건이 맞으면 그 틱에 시작, `저장`은 지정 만료 틱까지 보관, `무시`는 저장 없이 폐기를 뜻한다.

| 틱 시작 상태 | 수평 입력 | 점프 누름 | 내려가기 누름 | 공격 누름 | 회피 누름 |
|---|---|---|---|---|---|
| Neutral·지상 | 실행 | 실행 | 지지 발판이 유효하면 실행 | 실행 | 준비됐으면 실행 |
| Neutral·공중 | 실행 | 코요테 유효 시 실행, 아니면 저장 | 무시 | 실행 | 준비됐으면 실행 |
| 공격 준비·유효·후딜 | 목표 속도 50% | 무시 | 무시 | 무시 | 무시 |
| Dodge | 실행 | 무시 | 무시 | 무시 | 무시 |
| Hitstun | 무시 | 무시 | 무시 | 무시 | 무시 |
| Eliminated·Countdown·Result | 무시 | 무시 | 무시 | 무시 | 무시 |

점프 누름은 키를 누르기 시작한 틱의 이벤트다. 계속 누르는 것으로 재발행하지 않는다. 입력 어댑터는 아래+점프를 `dropPressed` 하나로 정규화하고 `jumpPressed`를 동시에 만들지 않는다.

**Neutral의 동시 입력 결정 순서**

1. 사용 가능한 회피가 있으면 회피만 시작한다. 같은 틱의 점프·내려가기·공격과 기존 점프 버퍼를 지운다.
2. 회피가 불가능하면 남은 입력을 정상 처리한다. 내려가기가 유효하면 내려가기만 실행하고 공격·점프·버퍼를 지운다.
3. 내려가기가 불가능하면 그 요청만 버린다. 일반 점프로 바꾸지 않으며 같은 틱의 공격은 실행할 수 있다.
4. 현재 점프 입력 또는 유효한 점프 버퍼가 있고 점프할 수 있으면 점프를 실행한다. 이어서 같은 틱의 공격도 시작할 수 있다.
5. 점프를 실행하지 못하면 Neutral 공중에서 들어온 일반 점프만 버퍼에 저장한다. 이후 공격을 시작한다면 저장한 버퍼를 즉시 지운다.

따라서 점프+회피는 회피만, 내려가기+회피는 사용 가능한 회피만, 유효 내려가기+공격은 내려가기만, 점프+공격은 점프가 가능할 때 둘 다 실행한다. 세 입력 이상도 이 순서를 그대로 따른다. 행동 종료 직전 틱에 들어온 금지 입력도 버리며 다음 틱으로 넘기지 않는다.

**점프 버퍼와 코요테의 정확한 경계**

- 틱 b에 저장한 점프는 `b≤현재 틱<b+6`에서만 유효하다. b+5까지 가능하며 b+6부터 만료다. 새로운 허용 점프 누름이 있으면 해당 틱으로 갱신한다.
- 착지는 이동 단계에서 처리하므로 버퍼 점프는 다음 틱의 입력 단계에서 실행한다. 착지 순간 같은 틱에 다시 점프시키지 않는다. b+4에 착지하면 b+5에서 실행 가능하고, b+5에 착지하면 b+6에는 만료다.
- 틱 e의 이동 중 걸어서 지지를 잃으면 코요테는 e+1~e+6의 입력 단계에서 유효하고 e+7부터 만료다. `coyoteExpiresExclusive=e+7`로 보관한다.
- 점프·내려가기·피격은 코요테를 지운다. 공격·회피 진입은 점프 버퍼를 지운다. 피격은 둘 다 지운다. 행동 중 버퍼를 새로 저장하지 않는다.
- 일반 착지 시 코요테는 필요 없으므로 지운다. 착지한 상태에서 점프할 수 있는지는 지지 상태로 결정한다. 행동이 끝나기 전 입력을 저장하지 않았으므로 착지만으로 금지 동작이 실행되지 않는다.

### 4.2 밀치기 초기값

| 항목 | 초기값 |
|---|---:|
| 준비 동작 | 8틱 |
| 공격 유효 시간 | 3틱 |
| 공격 후 빈틈 | 19틱 |
| 총 행동 길이 | 30틱, 약 0.5초 |
| 공격 사각형 | 가로 1.0 × 세로 1.2 |
| 공격 중심 | 발밑 기준 전방 0.75, 위쪽 0.8 |
| 수평 넉백 | 공격 방향으로 9.0 단위/초 |
| 수직 넉백 | 위쪽으로 4.5 단위/초 |
| 피격 경직 | 14틱 |
| 직접 체력 피해 | 0 |

공격 시작 시 바라보는 방향을 고정한다. 공격 도중 반대 입력으로 공격 판정이 뒤집히지 않는다. 공격 중 수평 조작 목표 속도는 기본의 50%이며, 이미 발생한 외부 넉백은 이 제한으로 잘라내지 않는다. 점프·회피·발판 내려가기는 공격 중 새로 시작할 수 없다. 중력과 낙하는 계속된다.

첫 공격 틱의 나이는 0이다. 공격 나이 0~7은 준비, 8~10은 유효, 11~29는 후딜이다. 판정 적용 후 나이를 증가시키고, 30이 되면 Neutral로 복귀한다. 이 정의를 테스트에서도 동일하게 사용한다.

### 4.3 적중 처리

1. 이동을 완료한 동일 틱의 좌표로 모든 유효 공격과 피격 상자를 수집한다.
2. 회피 무적 여부, 탈락 여부, 공격별 중복 적중 기록을 확인한다.
3. 유효 적중 목록을 확정한 뒤 한꺼번에 적용한다.
4. 대상의 기존 수평 속도를 넉백 방향 속도로 교체하고, 수직 속도는 `max(기존 수직 속도, 4.5)`로 적용한다.
5. 피격 경직을 시작하고 진행 중인 공격·회피를 취소한다.
6. 적중 이벤트에 공격자·대상·공격 ID·틱·위치를 기록한다.

하나의 공격은 한 대상에게 한 번만 적중한다. 공격 유효 시간이 3틱이라고 3번 밀리지 않는다. 같은 틱에 서로 유효 적중하면 양쪽 모두 맞는다. P1을 먼저 처리했다는 이유로 P2의 이미 성립한 공격을 지우지 않는다.

**넉백의 단일 속도 계약**

피격이 틱 k의 이동 이후 확정되면 `velocity.x=공격 방향×9`, `velocity.y=max(기존 값,4.5)`로 덮어쓴다. 같은 틱에 위치를 추가 이동시키지 않는다. 지지 상태·코요테·점프 버퍼를 즉시 해제하고 `hitstunUntilExclusive=k+15`로 설정한다. k+1~k+14의 14회 이동 단계가 제어 불가이며 k+15부터 일반 제어가 가능하다.

| 상황 | 수평 속도 처리 | 수직·상태 처리 |
|---|---|---|
| 경직 중·지상 또는 공중 | 입력·마찰·무입력 감속 모두 적용하지 않고 유지 | 중력과 지형 충돌은 적용 |
| 경직 중 착지 | 수평 넉백 유지 | 하향 속도만 0, 남은 경직 유지 |
| 벽 충돌 | 벽 바깥을 향하는 수평 속도만 0 | 경직 유지, 반사·벽 피해 없음 |
| 경직 종료·지상·입력 있음 | 현재 속도에서 목표 `6×moveX`를 향해 초당 60만큼 변경 | 일반 지상 규칙 |
| 경직 종료·지상·입력 없음 | 현재 속도에서 0을 향해 초당 75만큼 변경 | 일반 지상 규칙 |
| 경직 종료·공중 | 현재 속도에서 목표 `6×moveX`를 향해 초당 24만큼 변경 | 일반 중력·낙하 규칙 |
| 경직 중 새로운 유효 피격 | 새 공격의 수평 넉백으로 교체 | 수직 max 규칙 적용, 새 피격 틱으로 경직 갱신 |

수평 변경은 `MoveTowards(현재 값, 목표 값, 가속도×dt)`에 해당하는 연산이며 속도를 ±6으로 즉시 잘라내지 않는다. 경직 종료 틱의 지상·공중 선택은 틱 시작 지지 상태를 따른다. 경직 중 벽에 막힌 뒤에는 입력으로 다시 가속하지 못한다.

장애물과 추가 피격이 없는 경직 14틱 동안 수평 이동 거리는 `9×14/60=2.1`단위다. 착지해도 이 계약은 유지된다. 이는 이동 계약의 기준값이며 공격 한 번의 총 이동 거리에는 경직 이후 이동도 포함된다.

### 4.4 회피 초기값

회피는 이동 돌진이 없는 짧은 회피 동작으로 시작한다. 절벽을 자동으로 넘어가거나 방향키 없이 이동시키지 않는다.

- 전체 행동 시간: 15틱.
- 밀치기 무적: 회피 나이 0~8, 총 9틱.
- 취약한 종료 동작: 나이 9~14, 총 6틱.
- 재사용 대기시간: 시작 틱부터 60틱.
- 이동 입력과 중력은 유지하지만 새 점프·공격·내려가기는 시작할 수 없다.
- 막 피해, 바닥 추락에는 무적이 적용되지 않는다.
- 무적 중에는 캐릭터 테두리와 잔상을 표시하고, 종료 동작은 별도 모양으로 표현한다.

공격 유효 시간이 회피 무적이 끝난 뒤까지 남아 있으면 그 틱에 맞을 수 있다. 따라서 공격별 적중 기록은 실제 적중했을 때만 남긴다.

## 5. 하얀 막과 체력

### 5.1 위치와 시간표

막은 화면 효과가 아니라 월드 Y좌표를 가진 수평 경계다. 그 위가 위험 지역이며 아래가 안전 지역이다. 카메라가 움직여도 막의 월드 위치는 변하지 않는다.

첫 맵의 막 시간표는 다음 제안값을 사용한다.

| 경기 경과 시간 | 막의 Y좌표 | 역할 |
|---|---:|---|
| 0초 | 34 | 시작 발판 위에서 대기 |
| 5초 | 34 | 초반 조작 여유 종료 |
| 45초 | 22 | 중층 이동 유도 |
| 85초 | 10 | 하층 교전 유도 |
| 120초 | 1 | 최하층도 무조건 안전하지 않게 함 |

구간 사이 위치는 선형 보간한다. 막 위치를 매 프레임 조금씩 더하는 방식보다 경과 틱에서 직접 계산하여 누적 오차를 줄인다. 모든 키프레임은 시간 오름차순, Y 내림차순이어야 한다.

### 5.2 피해와 경고

- 최대 체력: 100.
- 발밑 Y가 막 Y보다 클 때만 노출이다. 경계와 같으면 안전하다.
- 노출된 매 틱에 0.2 피해를 적용한다. 60틱당 12 피해이므로 연속 노출 생존 시간은 약 8.33초다.
- 체력은 정수 내부 단위로 보관한다. 예: 최대 1,000, 틱당 2 차감, UI는 10으로 나누어 표시한다.
- 노출 틱마다 감소하므로 안전 구역을 잠깐 오가는 행동으로 피해 주기를 초기화할 수 없다.
- 초기안에는 자연 회복, 방어력, 체력 아이템을 넣지 않는다.

막까지 수직 여유가 3단위 이내면 경고 표시를 시작한다. 단, 이미 노출되었으면 접근 경고 대신 체력 감소 상태를 강조한다. 막 위쪽은 옅은 흰색으로 덮되 캐릭터와 발판 윤곽을 읽을 수 있게 한다. 체력 감소를 색 하나로만 전달하지 말고 아이콘과 소리를 병행한다.

고정 높이에서 기다렸을 때 막 도달 시간과 남은 생존 시간을 계산해 디버그 화면에 표시한다. 막 피해 때문에 대부분의 경기가 끝나면 먼저 막 시간표·피해량을 점검하고, 밀치기 위력을 무작정 높이지 않는다.

### 5.3 마지막 15초 전용 실험

현재 막은 85초 Y=10에서 120초 Y=1까지 선형 하강한다. Y=2에 도달하는 시각은 `85+(10-2)×35/9=116.111…초`다. 끝 시각 표본을 쓰는 60틱 시뮬레이션에서 Y=2에 정지한 플레이어는 마지막 234틱에 노출되어 체력 46.8을 잃는다. 체력 100이면 53.2가 남으므로 막이 자동으로 결판을 낸다고 가정하면 안 된다. 점프하면 노출이 더 일찍 시작될 수 있다.

전체 맵 제작 전에 경기 상태를 정확히 105초, 남은 시간 900틱으로 불러오는 장면을 만든다. 막은 Y=34에서 재시작하지 않고 실제 시간표상의 Y=34/7≈4.857로 초기화한다. 발판은 중심 X=0, Y=2, 폭 8의 1개, 두 플레이어는 X=±1에서 시작한다. 벽·탈락선은 기본값이고 속도·버퍼·경직은 0, 회피는 사용 가능하다.

초기 체력은 (100,100), (100,60), (60,60), (40,100)으로 나누고 슬롯을 바꿔 시험한다. 다음 행동을 비교하되 상대는 자유롭게 대응한다.

- 적극적으로 밀치고 추락시키기.
- 체력을 아끼며 회피·이동으로 버티기.
- 마지막 점프의 최고점이 종료 시각에 가깝도록 맞추기.

실제 모터에서 점프 최고점 틱을 먼저 측정한다. 이론상 `11/30≈0.367초`는 참고값이다. 마지막 2초의 행동, 종료 높이, 체력, 적중, 승패가 뒤집힌 틱을 기록한다. 양쪽 모두 자유롭게 행동하는 경기와 특정 전략의 반복 시험을 구분한다.

종료 직전 점프가 유효한 전술인 것 자체는 실패가 아니다. 상대가 공격·착지 요격·자신의 점프로 대응할 수 있는지, 앞선 체력·위치 선택이 마지막 15초에도 의미가 있는지를 본다. 점프 타이밍 외의 선택이 사라지는 양상이 반복되면 규칙을 재검토한다. 이 실험은 원래 막 시간표의 끝 구간만 검증하며, 전체 경기에서 체력이 보존되는 빈도는 별도 플레이 테스트로 확인한다.

대안은 현재 규칙의 시험 결과를 본 뒤 하나씩 비교한다. ‘마지막으로 밟은 발판 높이’는 추락 중에도 과거 높은 발판 점수를 유지할 수 있고, ‘최근 일정 시간 평균 높이’는 직관성과 기록 부담을 바꾼다. 어느 쪽도 자동 채택하지 않는다. 변경하면 HUD, 결과 설명, 저장 데이터, 테스트까지 함께 개정한다.

## 6. 맵 제작 기준

### 6.1 첫 맵 구조

초기 범위는 X=-9~9, 최상층 발판 Y=30, 최하층 발판 Y=2로 잡는다. 맵 경계는 이 범위를 고정하고, 배경 건물은 충돌 지형과 분리한다.

| 구역 | 높이 범위 | 발판 배치 의도 |
|---|---|---|
| 상층 | Y=22~30 | 넓은 발판, 첫 밀치기 이후 회복 기회 |
| 중층 | Y=10~22 | 좁은 발판과 우회 발판 혼합 |
| 하층 | Y=2~10 | 추락 위험 증가, 마지막 착지 선택 |

시작 발판은 X=-6~6, Y=30에 둔다. P1/P2는 X=-3/+3에서 서로 마주 보고 시작한다. 첫 맵은 좌우 대칭으로 만들고 위치 교대 테스트를 수행한다.

초기 발판 폭은 넓은 발판 6~10, 좁은 발판 2.5~4단위다. 일반 층간 간격은 3~4단위로 두되, 각 주요 구역에는 높이차 1.5~1.8단위의 중간 발판 경로를 둔다. 그렇지 않으면 점프 높이 약 2단위인 캐릭터는 상대보다 한 층 아래로 내려간 뒤 재접근할 수 없다.

중간 발판은 맵 전체를 무한히 쉽게 되올라가는 사다리가 되지 않도록 배치한다. 한 구역에서 높이를 회복하는 경로와 계속 하강하는 경로가 모두 존재해야 한다. 상대와 오랫동안 따로 떨어져 있는 상황은 배치 문제로 기록한다.

### 6.2 이동 가능성 검증

발판을 노드로, 실제 모터로 도달할 수 있는 이동을 방향 간선으로 기록한다. 상향 점프와 하향 낙하는 별도 연결이다. 단순 중심 간 거리만으로 연결을 판정하지 않는다.

각 주요 발판에서 다음을 확인한다.

1. 정상 입력으로 아래쪽의 안전한 발판을 선택할 수 있다.
2. 발판 중앙에서 한 번 맞았을 때 적어도 하나의 착지 가능 경로가 있다.
3. 가장자리에서 맞았을 때는 높이 손실 또는 탈락 위험이 유의미하다.
4. 상대가 한 단계 아래에 있을 때 재교전할 경로가 있다.
5. 벽과 발판이 영구적인 안전 주머니를 만들지 않는다.
6. 캐릭터가 낙하하는 동안 선택할 다음 발판이 화면에 표시된다.

자동 도달 검사는 후보 경로를 찾는 도구이며, 사람이 실제로 판단하고 조작할 수 있는 난도까지 보장하지 않는다. 손으로 점프·피격·회피 후 착지를 각각 플레이해 확인한다.

### 6.3 무너지는 발판: 후속 기능

고정 발판에서 기본 재미를 확인한 뒤 추가한다. 상태는 `Intact → Warning → Broken`이다. 첫 착지 후 72틱이 지나면 무너지고, 첫 착지 즉시 균열과 진행 표시를 시작한다. 두 명이 함께 밟아도 타이머가 두 번 시작되거나 초기화되지 않는다.

무너짐은 틱 시작 시 반영해 그 틱의 이동 충돌에서 제외한다. 발판 위 캐릭터는 낙하를 시작한다. 첫 버전에서는 경기 중 재생성하지 않고, 재경기 때 원상 복구한다. 지연 시간과 경고 상태는 맵 데이터로 설정한다.

### 6.4 전체 맵 이전의 전투 실험 장면

먼저 아래 고정 발판 5개로 작은 장면을 만든다. 단위와 단방향 충돌 규칙은 본문과 같다. 벽은 X=±9, 탈락선은 Y=-2다. 막은 이 실험에서 비활성화한다.

| 발판 ID | 중심 X | 상단 Y | 폭 | 용도 |
|---|---:|---:|---:|---|
| T0 | 0 | 8 | 3 | 가장자리 압박 |
| T1 | -2 | 6.5 | 2.5 | 좌측 회복·재접근 |
| T2 | 2 | 6.5 | 2.5 | 우측 회복·재접근 |
| T3 | 0 | 5 | 4 | 하층 재교전 |
| T4 | 0 | 2 | 8 | 추락 후 회복 관찰 |

T0에서 공격자 X=-0.1, 방어자 X=1.0으로 시작하고 서로 마주 보게 한다. 좌우 반전과 조작자 역할 교대도 실시한다. 두 캐릭터는 정지 시작과 방어자가 중앙 방향 속도 6을 가진 시작을 각각 시험한다. 공격 준비 8틱의 최대 속도 이동량 0.8은 후자에 해당하며 정지 상태 가속 거리와 구분한다.

**가설:** 통과가 가능해도 공격자의 위치·공격 시점 선택으로 중앙 복귀를 견제할 수 있고, 방어자가 회피나 반격을 선택할 이유가 있다.

1. 기준안 A: 현재 통과 규칙과 공격 범위로 시험한다. 방어자는 우선 이동만, 다음에는 모든 행동을 사용한다. 공격자는 자유롭게 대응한다.
2. 각 시작 조건에서 10회, 좌우와 역할을 교대해 반복한다. 중앙 영역 `|x|≤0.3`으로 2초 안에 피격 없이 복귀한 비율, 공격 적중, 회피 사용, 추락, 재교전 시간을 기록한다.
3. 이동만으로 무피격 복귀가 80% 이상 반복되면 압박 가설 재검토 대상으로 표시한다. 이 수치는 문제 탐지용 임시 기준이며 작은 표본으로 재미를 확정하지 않는다.
4. 재검토 시 한 번에 하나만 바꾼다. 먼저 공격 범위 또는 준비 시간의 한 설정을 비교하고, 그래도 압박이 성립하지 않으면 몸체 충돌 실험안 B를 검토한다.
5. B를 구현할 경우 공중 접촉·회피 중 통과·벽 끼임·동시 접근의 분리 방식까지 별도 규칙을 정한 뒤 시험한다. 본 개정은 B를 기본 규칙으로 채택하지 않는다.

공격 유도→회피→반격 사례와 공격자의 반대 방향 견제 사례를 영상으로 확보하기 전에는 전체 맵을 확장하지 않는다. 스크립트의 탈출 성공률과 사람이 느끼는 선택의 재미를 함께 판단한다.

## 7. 카메라·화면·피드백

### 7.1 카메라 정책

같은 화면에 두 플레이어와 아래쪽 착지 공간을 담는 공동 카메라로 시작한다. 플레이어 경계 상자를 기준으로 좌우 여백 2, 위 여백 2, 아래 여백 5단위를 확보한다. 화면 비율에 맞추어 필요한 수평·수직 크기 중 큰 값을 사용한다.

확대·축소는 부드럽게 보간하되, 낙하 중 캐릭터가 화면 밖으로 나가면 추적을 우선한다. 막 전체를 보여 주기 위해 캐릭터가 지나치게 작아지도록 축소하지 않는다.

높이 차이가 커지는 게임이므로 공동 카메라만으로 해결하려 하지 않는다. 초기 기준으로 두 플레이어의 높이 차이가 12단위를 넘는 상태가 30틱 지속되면 좌우 분할 화면으로 전환한다. 각 화면은 해당 플레이어와 다음 착지 지점을 추적한다. 높이 차이 8단위 미만이 60틱 지속되면 다시 합친다. 분할·복귀 기준 차이는 화면 전환 반복을 방지한다.

이 수치는 화면 비율별로 조정한다. 각 화면에서 캐릭터 높이가 화면 높이의 약 6%보다 작아지면 가독성 실패로 기록한다. 분할 화면에는 상대가 위/아래 어느 방향인지, 대략적인 높이 차이를 표시한다.

### 7.2 HUD와 결과

- 각 플레이어의 체력, 회피 준비 상태, P1/P2 표식.
- 남은 시간, 마지막 10초의 명확한 카운트다운.
- 막 접근·노출 상태와 현재 높이 우위.
- 결과 원인: 추락, 막 피해, 시간 종료 높이, 체력 비교, 동시 탈락.
- 무승부일 때 동시 탈락인지 시간 종료 동률인지 표시.

체력은 정수로 올림 표시하되 내부 값 0에서만 0을 표시한다. 높이 동률 기준 0.1은 HUD에도 반영하여 UI상 동률인데 내부적으로 한쪽이 이기는 혼란을 줄인다.

### 7.3 타격감

밀치기 준비에는 몸을 낮추거나 팔을 당기는 신호, 유효 시간에는 전방의 짧은 공격 궤적, 후딜에는 복귀 동작을 넣는다. 적중 시 짧은 피격 번쩍임, 효과음, 작은 카메라 흔들림을 사용한다.

첫 시제품에서는 시뮬레이션을 멈추는 히트스톱을 넣지 않는다. 필요하면 이후 모든 경기 시간·공격·막 처리와 일관된 별도 규칙으로 추가한다. 화면 흔들림은 끌 수 있어야 하며, 렌더링 오프셋만 바꾸고 물리 좌표에 영향을 주지 않는다.

## 8. 프로그램 구조와 내부 계약

### 8.1 모듈 책임

| 모듈 | 책임 | 직접 수정하지 않을 상태 |
|---|---|---|
| MatchSimulation | 틱 순서, 경기 상태, 최종 결과 | UI 내부 상태 |
| InputAdapter | 장치 입력을 틱 명령으로 변환 | 체력·좌표 |
| PlayerMotor | 가속·중력·이동 충돌·착지 | 승패·공격 적중 |
| ActionController | 공격·회피·경직 상태 진행 | 다른 플레이어 체력 |
| CombatResolver | 공격 수집, 적중 검증, 넉백 이벤트 | 카메라 |
| HazardSystem | 막 위치, 노출, 체력 피해 | 입력 바인딩 |
| PlatformSystem | 발판 상태, 붕괴 예약 | 경기 결과 |
| ResultResolver | 탈락·시간 종료 결과 계산 | 물리 이동 |

| ReplayRecorder | 틱 입력·이벤트·스냅샷 기록 | 실제 경기 진행 |

렌더링 코드가 체력을 깎거나 애니메이션 이벤트가 적중을 확정하게 만들지 않는다. 게임 규칙의 상태는 시뮬레이션이 소유하고 다른 모듈은 명령이나 이벤트로 연결한다.

### 8.2 최소 데이터 구조

```text
InputFrame
  tick, playerId, moveX[-1..1]
  jumpPressed, dropPressed, attackPressed, dodgePressed

PlayerState
  playerId, feetPosition, velocity, facing
  groundedPlatformId, ignoredPlatformId
  actionState, actionAgeTicks, dodgeReadyTick
  healthUnits, attackSequence, hitTargets
  coyoteExpiresExclusive, jumpBufferExpiresExclusive
  hitstunUntilExclusive
  eliminated, eliminationReasons

MatchState
  schemaVersion, buildId, rulesetHash, mapHash
  matchId, phase, tick, remainingTicks
  players[2], hazardY, platformStates, result

CombatEvent
  eventId, tick, attackerId, targetId, attackId
  hitPosition, knockbackVelocity

MatchResult
  winnerIdOrNull, reason, finalTick
  finalHeights[2], finalHealthUnits[2], eliminationReasons[2]
```

틱은 정수로 기록한다. 재경기마다 공격 ID·이벤트 ID·적중 목록·이전 입력 상태를 초기화한다. `eventId`는 경기 ID와 틱, 틱 내 순서를 조합해 이벤트 중복 재생을 막는다.

### 8.3 내부 함수 경계

```text
StepMatch(state, inputFrames, config) -> nextState, events
StepMotor(player, input, collisionWorld, config) -> player
CollectHits(players, config) -> hitCandidates
ResolveHits(hitCandidates, players) -> hitResults
EvaluateResult(state) -> resultOrNull
BuildRenderSnapshot(state, events) -> snapshot
```

이것은 구현할 함수 계약이며 특정 엔진의 실제 API 이름이 아니다. 로컬 시제품에는 HTTP 서버나 데이터베이스 API가 필요하지 않다. 설정 파일, 맵 파일, 로컬 기록만으로 시작한다.

### 8.4 한 틱의 처리 순서

1. 시작 시각에 예약된 발판 붕괴, 경직 종료, 쿨다운과 버퍼·코요테 만료를 반영한다.
2. 두 명의 입력을 확보하고 상태별 행동 허용 여부를 계산한다.
3. 4.1절의 우선순위로 회피·내려가기·점프·공격 시작을 처리한다.
4. 두 명의 이동·중력·지형 충돌을 처리한다.
5. 이동 후 좌표와 행동 상태로 공격 후보를 모두 수집한다.
6. 유효 적중 목록을 확정하고 넉백·경직을 일괄 적용한다.
7. 현재 경과 틱의 막 위치를 계산하고 두 명의 노출 피해를 처리한다.
8. 바닥 경계와 체력을 기준으로 두 명의 탈락을 함께 계산한다.
9. 남은 경기 틱을 1 줄이고 승패 우선순위에 따라 결과를 평가한다.
10. 계속 진행한다면 공격·회피의 행동 나이를 갱신한다. 버퍼·코요테·경직은 절대 만료 틱으로 판정하며 별도의 남은 틱 감소 연산을 섞지 않는다.
11. 이벤트와 스냅샷을 외부에 전달한다.

경과 시간 0에서 첫 틱을 시작하고, 해당 틱의 이동·환경 처리는 끝 시각 `(tick+1)/60`을 기준으로 한다. 이 기준으로 막의 최종 키프레임과 시간 종료 틱을 일치시킨다. 입력 행동은 틱 시작에서 판정한다.

## 9. 설정·저장·개발 도구

### 9.1 데이터 중심 설정

수치와 맵을 코드에 흩어 놓지 않고 다음 파일로 나눈다. 아래 경로는 향후 프로젝트 구조 예시다.

```text
config/ruleset.json       경기 시간, 승패, 체력, 막 규칙
config/player.json        이동, 공격, 회피 수치
maps/tower_01.json        발판, 스폰, 경계, 카메라 범위
src/simulation/           경기·이동·전투·환경 처리
src/presentation/         카메라·HUD·사운드·애니메이션
src/input/                장치별 입력 변환
tests/scenarios/          재현 가능한 규칙·충돌 시나리오
tools/                    기록 분석, 설정·맵 검사
```

경기 시작 시 설정을 한 번 읽어 고정한다. 편집 중 바뀐 수치는 다음 경기부터 적용하고 기록에 설정 해시를 남긴다. 맵 데이터에는 발판 ID, 중심 X, 상단 Y, 폭, 종류, 붕괴 지연 틱을 기록한다.

시작 시 중복 발판 ID, 음수 폭, 잘못된 스폰, 역행하는 막 키프레임, 0 이하 경기 시간, 공격 구간 길이 불일치를 검사한다. 잘못된 설정은 조용히 보정하지 말고 어떤 항목이 문제인지 표시한다.

### 9.2 개발용 화면

개발 빌드에는 충돌 상자, 공격 범위, 발밑 좌표, 속도, 행동 나이, 지지 발판 ID, 막 경계, 회피 무적, 마지막 적중 사유를 표시한다. 한 틱 진행, 일시정지, 지정 위치 이동, 체력 설정, 공격 반복 봇을 제공한다.

고정 틱만으로 서로 다른 환경의 물리 결과가 완전히 같다고 가정하지 않는다. 재현 기록에는 빌드·설정·맵 해시와 입력뿐 아니라 주기적 스냅샷을 포함한다. 재생 결과가 달라지면 최초 차이 틱을 보고한다. 임의 난수를 사용하는 후속 기능에는 시드도 기록한다.

### 9.3 로컬 저장

설정에는 입력 바인딩, 음량, 화면 흔들림, 표시 옵션을 저장한다. 경기 기록에는 익명 슬롯 P1/P2, 길이, 결과, 주요 이벤트, 설정 버전만 저장하면 충분하다. 초기 단계에서 계정 정보나 개인 식별 데이터를 수집할 이유는 없다.

설정 파일은 임시 파일에 쓴 뒤 교체하여 쓰기 중 종료에 대비한다. 파일이 손상되면 기본값으로 시작하고 복구 사실을 알린다. 디버그 경기 기록은 크기·개수 제한을 둔다.

## 10. 온라인 확장 지침

온라인은 로컬 시제품의 조작·전투·카메라가 통과된 뒤 착수한다. 아래 내용은 확장 설계이며, 특정 네트워크 라이브러리 채택이나 최신 API 검증을 의미하지 않는다.

### 10.1 권한 구조

온라인 시제품은 권한을 가진 서버가 경기 틱·체력·적중·승패를 계산하는 구조로 설계한다. 방장 프로세스에 서버를 함께 둘 수 있지만 방장 지연 이점과 방장 종료 시 경기 중단이 남는다. 공개 경쟁 서비스의 서버 운영 방식은 별도 결정한다.

클라이언트는 자신의 입력을 보내고 서버는 결과 상태를 보낸다. 클라이언트가 보낸 좌표·적중 성공·승리 주장을 그대로 적용하지 않는다. 이동값 범위, 입력 빈도, 틱 범위, 공격·회피 상태 제약을 서버에서 검증한다.

| 메시지 | 주요 필드 | 처리 원칙 |
|---|---|---|
| JoinRequest | 프로토콜·빌드·설정·맵 해시 | 불일치 시 입장 거부와 이유 안내 |
| InputBatch | 입력 순번, 대상 틱, 최근 입력 묶음 | 중복 제거, 허용 틱 범위 검증 |
| StateSnapshot | 서버 틱, 마지막 처리 입력, 전체 경기 상태 | 클라이언트 보정 기준 |
| MatchFinished | 결과, 최종 틱, 원인 | 서버 결과만 최종 표시 |

### 10.2 지연과 동기화

서버 시뮬레이션은 60틱, 상태 전송은 초기 20회/초로 실험한다. 클라이언트는 자기 이동을 예측하고 상대는 수신 상태 사이를 보간한다. 서버 상태와 다르면 마지막 확인 입력 이후를 재적용한다. 예측되지 않은 발판 붕괴·피격도 보정 대상에 포함한다.

첫 온라인 버전에서는 공격 판정을 과거 위치로 되감는 보상을 넣지 않는다. 서버 틱에서 유효한 공격만 처리하고, 실제 지연 실험으로 조작성을 평가한다. 이 방식이 회피·밀치기 체감을 만족시키지 못하면 제한된 과거 판정 또는 롤백을 별도 기술 과제로 삼는다. 로컬 동작이 좋다는 이유만으로 온라인 품질을 완료 처리하지 않는다.

입력이 빠졌을 때는 마지막 수평 입력을 최대 6틱만 유지하고 이후 중립으로 전환한다. 점프·공격·회피의 누름 이벤트는 반복 생성하지 않는다. 늦게 도착한 입력을 현재 틱에 무조건 실행하지 말고 폐기 규칙과 허용 지연을 명시한다.

RTT 30/80/150ms, 지터 20ms, 손실 1%/3% 조건을 재현하여 피격 위치 오차와 보정 빈도를 기록한다. 서버 결과가 일치하는 것과 플레이가 쾌적한 것은 별도로 평가한다.

### 10.3 연결 종료

준비 화면에서 연결이 끊기면 경기를 시작하지 않는다. 경기 중 5초간 연결이 복구되지 않으면 연결 종료 패배로 처리하는 초기 규칙을 둔다. 대기 중 게임은 계속 진행하며 입력 누락 규칙을 적용한다. 서버 자체가 사라져 판정을 확정할 수 없으면 결과 미확정으로 표시한다. 시제품에서는 방장 이전과 경기 중 재접속을 지원하지 않는다.

## 11. 구현 순서와 단계별 완료 조건

기간은 팀 규모와 숙련도가 정해지지 않았으므로 확정 일정으로 제시하지 않는다. 앞 단계의 통과 조건을 만족한 뒤 다음 단계에 들어간다.

| 단계 | 실제 작업 | 제출물 | 통과 조건 |
|---|---|---|---|
| A. 실행 기반 | 프로젝트, 고정 틱, 설정 로더, 입력 슬롯 | 조작 가능한 실행 빌드 | 2인 입력이 독립적으로 동작 |
| B. 이동 | 가속·점프·착지·내려가기·벽 | 이동 테스트 맵 | 빠른 낙하 관통·이중 점프 오류 없음 |
| C. 전투 | 행동 상태, 공격, 회피, 넉백, 5개 발판 | 전투 테스트 장면·압박 실험 기록 | 판정 경계 통과, 통과 이동 압박 가설 검토 완료 |
| D. 경기 | 막, 체력, 시간, 결과, 재경기, 마지막 15초 실험 | 단판 빌드·종반 실험 기록 | 종료 원인 정확, 종반 지배 전략 검토 완료 |
| E. 맵·카메라 | 실제 맵, 공동/분할 화면, HUD | 전체 수직 맵 빌드 | 큰 높이 차이에서도 착지 판단 가능 |
| F. 플레이 검증 | 기록 수집, 위치 교대, 수치 조정 | 플레이 테스트 보고 | 재미 가설과 주요 실패 원인 확인 |
| G. 확장 | 붕괴 발판 또는 온라인 중 하나 | 해당 기능 시험 빌드 | 기본 규칙 회귀 없음 |

각 작업은 입력 조건, 변경할 모듈, 설정 키, 수락 조건을 가진 작은 작업 항목으로 나눈다. 예를 들어 ‘회피 구현’의 완료는 애니메이션이 나오는 것이 아니라 0~8틱 무적, 9~14틱 취약, 60틱 재사용 제한, 막 피해 적용을 모두 확인한 상태다.

엔진을 선택한 뒤에는 물리 충돌·입력·빌드 관련 공식 문서와 고정된 버전을 확인하고 프로젝트에 기록한다. 엔진 고유 컴포넌트와 이 문서의 모듈을 연결하되 게임 규칙은 유지한다.

### 12.3 물리·입력 통합 검증

- 최대 낙하 속도로 얇은 발판을 통과해도 착지한다.
- 아래에서 점프할 때 단방향 발판이 머리를 막지 않는다.
- 내려가기 직후 같은 발판에 다시 붙지 않고, 아래 발판에는 정상 착지한다.
- 코요테 종료 경계와 착지 직전 입력 버퍼가 정해진 틱만큼 동작한다.
- 피격으로 발판을 벗어났을 때 코요테 점프가 생기지 않는다.
- 공격 중 반대 입력을 넣어도 판정 방향이 뒤집히지 않는다.
- 30/60/144 표시 FPS에서 동일 환경·동일 틱 입력의 결과가 같다.
- 렌더링 지연을 넣어도 시간이 프레임 수에 따라 빨라지거나 느려지지 않는다.
- 긴 프레임 지연에서 틱을 조용히 건너뛰지 않는다. 처리 적체를 기록하고 표시 부하를 낮춘다.
- 장치 분리·재연결 후 입력이 고정되지 않는다. 로컬 대전은 장치 연결 해제 시 일시정지한다.
- 분할 화면 전환 중에도 막과 발판의 월드 좌표는 그대로다.

### 12.4 성능 확인

첫 실행 빌드를 만든 뒤 기준 PC의 CPU·GPU·메모리·해상도를 기록한다. 그 장치에서 1080p 60FPS를 초기 목표로 삼고 전체 맵, 분할 화면, 효과 중첩, 반복 재경기 상태를 측정한다. 기준 장치가 없는 상태에서 최소 사양을 확정하지 않는다.

평균 FPS뿐 아니라 긴 프레임, 메모리 증가, 틱 처리 적체를 확인한다. 경기 20회 재시작 후에도 이벤트 구독·캐릭터·발판 객체가 누적되지 않아야 한다. 최적화는 측정된 병목부터 수행한다.

## 13. 플레이 테스트와 밸런스 수정

### 13.1 기록할 항목

| 항목 | 확인할 문제 |
|---|---|
| 경기 길이·종료 원인 | 막이 전투를 대신 끝내는지 |
| 밀치기 시도·적중·헛침 후 반격 | 공격 남발 또는 지나친 방어 우위 |
| 피격 후 높이 손실·재착지 여부 | 한 번 맞으면 끝나는지, 맞아도 무의미한지 |
| 막 노출 시간·손실 체력 | 체력을 높이 유지 자원으로 사용하는지 |
| 두 플레이어의 높이 차이·비교전 시간 | 맵에서 서로 만나지 못하는지 |
| 스폰 위치별 승률 | 좌우 구조와 카메라의 비대칭 |
| 회피 성공·종료 동작 피격 | 회피가 실제 선택과 빈틈을 만드는지 |
| 패배 이유에 대한 플레이어 설명 | 규칙과 시각 정보가 납득 가능한지 |

공격 가능 거리 밖에서 공격·적중 없이 10초 이상 떨어져 있으면 비교전 구간으로 표시한다. 높은 곳에서 시간을 버는 전술까지 자동으로 문제로 간주하지 말고, 실제로 선택과 대응이 있었는지 영상을 함께 본다.

### 13.2 첫 테스트 절차

1. 최소 3쌍에게 기본 조작을 3분간 익히게 한다.
2. 각 쌍이 6경기를 치르며 매 경기 시작 위치를 교대한다.
3. ‘왜 졌는가’, ‘다음에는 무엇을 바꾸겠는가’, ‘상대 행동이 보였는가’를 묻는다.
4. 수치 기록과 응답이 일치하는지 비교한다.
5. 한 실험에서는 한 종류의 수치만 바꾸고 같은 방식으로 다시 비교한다.

18경기는 문제 발견용 표본이지 밸런스 확정 근거가 아니다. 평균 경기 길이 약 90~120초는 초기 목표지만, 짧은 경기가 재미있다면 길이를 억지로 늘리지 않는다.

### 13.3 증상별 조정 순서

| 증상 | 먼저 확인 | 수정 후보 |
|---|---|---|
| 공격만 연타하면 유리 | 헛친 후 실제 반격 가능한가 | 후딜 증가, 공격 중 이동 제한 |
| 아무도 먼저 공격하지 않음 | 준비 동작과 회피 반응 여유 | 준비 시간·사거리의 소폭 조정 |
| 한 번 밀리면 항상 탈락 | 아래 발판·공중 제어·경직 | 회복 발판 추가, 경직·넉백 조정 |
| 밀어도 높이 손실이 없음 | 발판 폭과 넉백 이동 거리 | 발판 폭·넉백 조정 |
| 위 플레이어가 계속 도망침 | 재접근 경로·막 도착 시점 | 중간 발판과 막 시간표 조정 |
| 먼저 내려간 플레이어가 할 일 없음 | 상향 경로와 착지 요격 가능성 | 높이차·우회 경로 조정 |
| 막 피해로만 대부분 종료 | 하강 경로의 가독성과 도달성 | 맵 경로 수정 후 막 피해 조정 |
| 시간 종료 직전 점프만 중요 | 마지막 교전 가능 여부 | 먼저 하층 구조를 수정하고 규칙 대안 실험 |

밸런스 변경 기록에는 이전 값, 새 값, 해결하려는 문제, 테스트 결과를 남긴다. 공격·이동·맵·막을 동시에 크게 바꾸면 무엇이 개선했는지 알 수 없으므로 피한다.

## 14. 출시 확장과 최종 인수 기준

외형 판매를 추가하더라도 충돌 크기, 준비 동작 길이, 공격 범위, 회피 무적, 이동 성능은 같아야 한다. 스킨별로 밝은 막·어두운 배경·겹침 상태에서 판독성을 확인한다. 효과음·잔상은 공격 시점을 숨기거나 과장하지 않아야 한다.

상점·결제·계정은 별도 제품 범위다. 첫 게임 시제품에 이를 억지로 결합하지 않는다. 공개 온라인 서비스로 확장할 경우 방 운영, 서버 비용, 버전 호환, 장애 대응, 결과 검증 정책을 따로 설계한다.

첫 시제품의 인수 조건은 다음과 같다.

- 처음 실행한 두 사람이 조작을 확인하고 한 경기를 끝낼 수 있다.
- 이동·밀치기·회피·막·추락·시간 종료 규칙이 본 문서와 일치한다.
- 동시 공격과 동시 탈락에서 슬롯 처리 순서에 따른 편향이 없다.
- 상층 피격 이후 회복과 재교전이 실제로 가능하다.
- 높이 차이가 커져도 각자의 다음 착지 지점을 판단할 수 있다.
- 모든 종료 원인이 화면과 경기 기록에 남는다.
- 반복 재경기가 이전 경기의 상태를 물려받지 않는다.
- 규칙 자동 검증과 실제 플레이 테스트 결과가 함께 제출된다.
- 실행 빌드, 소스, 실행 방법, 설정 파일, 맵 데이터, 알려진 문제가 함께 전달된다.

첫 구현 작업은 **캐릭터 두 명이 같은 발판에서 이동하고, 밀치고, 아래 발판에 다시 착지하는 장면**을 완성하는 것이다. 그 장면의 조작과 판정이 납득되면 막과 경기 종료를 연결하고, 마지막으로 전체 수직 맵과 카메라를 완성한다.
